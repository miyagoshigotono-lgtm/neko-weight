## 1. 目的と背景

猫4匹（8kg台1匹＝以下「対象猫」、5kg台3匹）を飼育。対象猫の減量が目的。

全体の作戦は2本立てで、本装置はそのうち片方を担う。

| | 対象猫（8kg台） | スリム猫3匹（5kg台） |
|---|---|---|
| 餌の場所 | 床（本装置） | 高所（自由摂取） |
| 量の制御 | 本装置で1日分を少量頻回に分割 | 制御しない |

**前提（確認済み）**：対象猫は高所に絶対に登らない。この前提の上に作戦全体が成立している。

**この装置が解く問題**：床に置き餌をすると対象猫が食べ放題になる。かといって識別機構（体重・画像・RFID）はコストと複雑さが見合わない。よって「識別せず、1日分を機械が小分けして時間差で出す」方式を採る。

## 2. 機構：弾倉式スクリューコンベア

### 基本方式

水平に置いた円筒パイプの中に一条スクリューを収める。**各ピッチが1回分の小部屋（弾倉）として機能する。**

- ピッチ数：**6**（＝1日6回分）。当初は9で設計したが、造形した実機は6部屋。1回あたりの量は1.5倍になり「少量頻回」の狙いはその分弱まる
- 1回の給餌 ＝ **スクリューを正確に1回転** ＝ 全部屋が1ピッチ前進 ＝ 9段目の中身が餌皿へ落下
- **ホッパー・タンクは持たない。** パイプ自体が貯蔵部を兼ねる

### なぜこの方式か

一般的なスクリューコンベアはホッパーから重力供給し、吐出量は充填率に依存する。本方式は**朝の手作業で各部屋に小分けする**ため、スクリューの容積特性に依存しない。したがって**吐出量の校正が不要**。

### 装填

パイプの上半円がヒンジで開く。毎朝、蓋を開けて各部屋に目分量で投入する。

- **ヒンジは出口と反対側（奥側）に置く。** 出口側に開くと開けた瞬間に餌が皿へ落ちる
- 上半割は洗浄性のためでもある（PLAの積層溝に油脂が溜まるため、分解洗浄できる構造が必須）

### 回転止めについて

内壁にリブは**設けない**。

- 低速回転では餌が重力に逆らって壁を登り、スクリューと共回りする事態は起きにくい
- 代わりに**パイプ内壁とスクリュー外径のクリアランスを狭く**取り、羽根を部屋の仕切りとして機能させる
- **クリアランスは「粒径の1/3〜1/2」を避けること。** その領域は粒が楔になって固着する最悪域。取るべきは 0.3〜0.5mm 程度のほぼゼロ側
- ペットボトル流用は**不採用**。断面が真円でなく、狭クリアランスが成立しないため。**パイプも3Dプリントする**

### 出口

- パイプ下面に**ちょうど1ピッチ幅**の開口を設ける
- **スクリューの羽根は開口部で終わらせる。** 羽根が開口より先に伸びていると、落ちるべき餌を押し越す
- 開口の下に餌皿を置く

### 造形

- パイプは上下半割で、それぞれ寝かせてプリント（反り対策・真円精度）
- 合わせ面は羽根の外径より僅かに逃がし、粒の噛み込みを防ぐ
- スクリューは芯に M6 全ネジ棒を通す前提で設計（軸方向に立てると層剥離で折れる）
- 猫に叩かれても倒れない重量と固定、および開かないラッチ

## 3. 駆動系

### 減速機（手持ち部品で自作）

手持ちのプラ歯車詰め合わせセットを使用。**ウォームギヤ1段 + 平歯車2段**の構成。

```
130系DCモーター → ウォーム(約1:40) → 平歯車2段(約1:9) → スクリュー軸
                                            合計 約1:360
```

- **ウォームのセルフロックが利点。** 出力側から逆転しないため、対象猫が皿側からスクリューを突いても動かない
- **ウォーム軸の軸受けは長穴（スロット）にする。** 中心距離と噛み合い深さがシビアなため、組んでから調整できるようにする
- 釘は2段目以降の軸に使用。ウォームはモーター軸へ直接圧入
- プラ製ウォームの高速回転による摩耗は問題にならない。稼働は**1日6回×約2秒＝12秒**のみ（1回転2.03秒を実測）

### 代替案

自作ギヤボックスが成立しない場合：秋月「DCギアードモーター 6V 減速比1:298」（¥900、無負荷35rpm / 定格28rpm、停動トルク1kgf・cm、停動電流140mA、軸φ3mm Dカット）。

**設計上の注意**：給餌器の成否をギヤボックスに賭けないこと。本題はスクリューとパイプの検証であり、減速機はそこへ至る道具に過ぎない。

## 4. 1回転の割り出し

スクリュー軸に円板を固定し、縁にネオジム磁石を1個埋める。**リードスイッチ MKA-10110**（A接点：磁石が近づくとON、5個入¥290、接点150V/0.5A、接触抵抗0.1Ω）で検出する。

- ガラス管に窒素封入されており、餌の粉・湿気の影響を受けない。摺動がないため摩耗もしない
- 磁石の強さ・距離・向きによる感度は**現物合わせで詰める**

### 検討したが採らなかった案

**自己保持回路**（MOSFETと並列に接点を入れ、マイコンは起動のキックのみ、停止は回路が自律的に行う）は部品もソフトも最小になるが、**原点で「開く」B接点が必要**。MKA-10110はA接点のため、この回路にはマイクロスイッチ＋カム（原点に30〜45度の切り欠き）が必要になる。今回は部品点数よりも構成の素直さを取り、**マイコン検出方式**を採用する。

## 5. 制御（Arduino Nano / ATmega328P）

### ピン割り当て

| ピン | 用途 | 備考 |
|---|---|---|
| D3 | MOSFETゲート出力 | |
| D4 | 装填完了ボタン入力 | 外付けプルアップ5.1kΩ＋1µF、押下でGND |
| D5 | リードスイッチ入力 | 外付けプルアップ5.1kΩ＋1µF、磁石検出でGND |
| D13 | 空き（オンボードLED） | 他と共用していないので動作表示に使える |
| D0 / D1 | 使用しない | USBシリアル（CH340）に接続。シリアル出力を使うため空けておく |

### Digispark から Arduino Nano への変更

当初は Digispark（ATtiny85）を使ったが、以下の問題で Arduino Nano（ATmega328P / 5V / 16MHz）へ移行した。

| 問題 | 内容 |
|---|---|
| **シリアルが無い** | ATtiny85 にハードウェアUARTが無く、動作状況を一切出力できない。リードスイッチが検出できているか、1回転に何秒かかるかを、回転角の目視とストップウォッチで推測するしかなかった。切り分けに数日を要した |
| **オンボードLEDがピンと共用** | 唯一の表示手段であるLEDがMOSFET出力と同じピンに載っており、独立した状態表示に使えない |
| **書き込み経路が脆い** | micronucleus + libusb。DLL欠落、USBハブ非対応、ブートローダーが5秒しか見えない等、書き込みだけで何度も止まった |
| **USB部が故障した** | 外部5VとUSBの同時接続が続いた結果と思われる。USBが死に、最終的にボード全体が動作しなくなった |

Nano は 5V / 16MHz なので、**2SK4017 のゲート駆動を含め回路は一切変更不要**。USB-シリアル変換は別チップ（CH340）が担当するため、マイコン本体のUSB故障という失敗モードが無い。P3/P4 がUSBに直結という制約も消える。

### 時刻管理

**RTCは使わない。** 毎朝の装填という工程が必ず入るため、**装填完了ボタンの押下時刻を起点**として相対時間で計時する。絶対時刻を知る必要がない。

- **WDTによるスリープ計時は禁止。** WDT発振器は128kHzの内蔵RCで誤差が±10%あり、1日で1〜2時間ずれる
- **`millis()` で計時する。** コンセント給電のため省電力は不要。内蔵発振の誤差は約1%で、1日なら十数分に収まり、毎朝リセットされるため累積しない

### 給餌スケジュール

起点から6回（＝部屋数）。**合計を14〜16時間に収める**（装填が多少遅れても最後が深夜にならないため）。

**ボタンを押した時点で1回目を出す。** すぐ回ることが「タイマーが始まった」という目に見える合図になる。これが無いと、スケジュールが本当に開始したのか人が確認できない。

間隔は一定ではない。**猫の昼寝を妨げないよう、日中に3時間の空きを作る。**

| 回 | ボタンから | 朝7時に押した場合 | 間隔 |
|---|---|---|---|
| 1 | 0分 | 7:00（ボタンと同時） | — |
| 2 | 90分 | 8:30 | 1.5時間 |
| 3 | 180分 | 10:00 | 1.5時間 |
| 4 | 300分 | 12:00 | 2時間 |
| 5 | 480分 | 15:00 | **3時間（昼寝）** |
| 6 | 540分 | 16:00 | 1時間 |

最後を16時に置くのは、飼い主が18〜19時に帰宅して食事を与えるため、それまでに空になっている必要があるから。

**時刻は固定ではない。** RTCを持たないので全てボタンを押した時刻からの相対であり、装填が遅れればその分だけ全体がずれる。

**朝を多めにしたい場合は、装填で調整する。** 手で小分けするため、先に出る部屋に多く入れればよい。吐出量の校正が不要という設計の利点がここで効く（§2）。

対象猫の睡眠時間帯は避ける（毎回起こしてしまうため）。具体的な時間割は運用しながら詰める。

### 1回の給餌シーケンス

```
1. モーター回転開始
2. リードスイッチが「離れた」と確定するまで待つ（磁石の検出範囲を抜ける）
3. そこから、回転開始後 MIN_RUN_MS を過ぎた上で「検出」が確定したら停止
4. TIMEOUT_MS を過ぎても検出できなければ強制停止し、その回は諦める
```

**当初は手順2を「開始から1秒間は無視する」固定の不感帯としていたが、実機で失敗した。** 磁石の検出範囲が想定より広く、固定時間が明けた時点でまだ磁石の上にいたため、即検出・即停止で1ピッチ回らなかった。**検出範囲が何度ぶんあるか事前に分からない**ため、時間ではなく「離れたことの確認」に変えた。

**MIN_RUN_MS（手順3）はノイズ対策。** 1回転が約2秒と分かっているので、1.2秒より前の検出は本物ではあり得ない。手順2とは独立した下限として効く。

**タイムアウト（手順4）も必須。** 詰まった際に「検出するまで回り続ける」と、モーターが焼けるかギヤが舐めるか、スクリューが折れる。詰まりの通知機能は不要（朝夕必ず様子を見る運用のため）だが、**機械を保護するための上限は要る**。

### 停電・再起動時の挙動

給餌回数のカウントは失われる。**復帰後は待機状態とし、人がボタンを押すまで一切動かさない。**

これは意図的な設計。停電を検知して「残り回数を出す」といった復旧動作を入れると、誤爆で1日分をまとめて排出する事故につながる。朝夕確認する運用なので、人がボタンを押し直せば済む。

### ボタンの操作体系

**短押しには機能を割り当てない。** ノイズや接触で誤って1日分の予定が始まるのを防ぐため、長押しのみを受け付ける。

| 操作 | 動作 |
|---|---|
| 電源投入後の1回目の**3秒長押し** | **原点出し。** リードスイッチが反応する位置まで送って止まる |
| 2回目以降の**3秒長押し** | **その場で1回目を給餌**し、そこからインターバルを開始 |
| 進行中の長押し | 無視する（起点のリセットによる出し過ぎを防ぐ） |

**長押しは3秒とする。** 猫が偶然ボタンに触れて1日分の予定が始まるのを防ぐため。猫の肉球が3秒間一定の力で押し続けることは考えにくい。

原点出しが要るのは電源投入後の1回だけ。以降は毎回の給餌が磁石の位置で終わるため、常に原点から始まる。

### ボタン入力のノイズ対策

**P0 にも P2 と同じ外付けプルアップ（5.1kΩ）とコンデンサ（1µF）が必要。** 給餌の直後にブラシノイズで「押された」と誤判定されると、予定外のタイミングで回り出す。ソフト側でも30ms連続でLOWの時だけ押下とみなす。

## 6. 回路

```
              5V(+) ──┬──────────────┐
                      │              │
                    [1N4007]      [モーター]
                    (カソード＝＋側)  │  ┬ 0.1µF（端子間）
                      │              │  ┴
                      └──────────────┤
                                     │
                                   Drain
        Digispark ──[220Ω]──── Gate  2SK4017
          (P0)              │      Source
                          [10kΩ]      │
                            │         │
              GND ──────────┴─────────┴──── 5V(−)
```

| 部品 | 役割 |
|---|---|
| 2SK4017 | モーターのスイッチング。130系は停動1〜2A流れるため2N7000（200mA）では焼ける |
| 1N4007 | 逆起電力の還流。**これが無いとMOSFETもリードスイッチも壊れる。** リードスイッチの接点は溶着すると止まらなくなる |
| 220Ω | ゲート直列。突入電流からマイコン出力を保護 |
| 10kΩ | ゲートプルダウン。**無いと電源投入時にモーターが勝手に回る** |
| 0.1µF | モーター端子間。ブラシノイズ抑制 |
| 470〜1000µF / 10V以上 | 5Vライン。起動時の突入を吸収する。**無いとモーター始動時の電圧降下でマイコンがリセットし、その日の計時が飛ぶ** |
| 4.7k〜10kΩ | P2の外付けプルアップ。**内蔵プルアップ（20〜50kΩ）だけではモーターのブラシノイズでP2が誤ってLOWと読まれる**（実機で確認済み。リードスイッチの状態と無関係に、モーター始動直後に必ず誤検出した） |
| 0.1µF（2個目） | P2 ↔ GND。上のプルアップと合わせてRCフィルタを構成し、ノイズのスパイクを鈍らせる。時定数は1ms以下なので検出の遅れは問題にならない |

- **GNDは必ず共通にする**（電源を分ける場合もマイナス側は接続）
- 電源：本番は 5V USB ACアダプタ（**2A以上**）。ベンチテストは単3×2本（3V）
- **モーターの電流をDigisparkの基板に通さない。** アダプタの5Vからモーターとスイッチング回路へ直接配線し、Digisparkとは電源ラインとGNDで並列に繋ぐ
- **電池運用は不採用。** Digisparkの待機電流が15〜20mAあり、単3×4本でも約6日しか持たない。モーターの消費は全体の0.2%に過ぎず、食っているのは待機中のマイコン。加えて新品アルカリ4本は6.4Vとなり、ATtiny85の最大定格5.5Vを超える

### 配線表

マイコンは **Arduino Nano（ATmega328P / 5V / 16MHz）**。Digispark から移行した経緯は §5 を参照。

電源

| From | To |
|---|---|
| ACアダプタ +5V | 5Vライン |
| ACアダプタ GND | GNDライン |
| Nano **5V** ピン | 5Vライン |
| Nano **GND** ピン | GNDライン |

モーター駆動

| From | To |
|---|---|
| Nano **D3** | 220Ω 片端 |
| 220Ω 他端 | 2SK4017 **G** |
| 2SK4017 **G** | 10kΩ → GNDライン |
| 2SK4017 **S** | GNDライン |
| 2SK4017 **D** | モーター端子① |
| モーター端子② | 5Vライン |
| 0.1µF | モーター端子① ↔ ② |
| 1N4007 **アノード** | モーター端子①（D側） |
| 1N4007 **カソード**（帯） | モーター端子②（5V側） |
| 電解コン **＋** | 5Vライン |
| 電解コン **−** | GNDライン |

入力

| From | To |
|---|---|
| リードスイッチ 片端 | Nano **D5** |
| リードスイッチ 他端 | GNDライン |
| 5.1kΩ | Nano **D5** ↔ 5Vライン |
| 1µF | Nano **D5** ↔ GNDライン |
| ボタン 片端 | Nano **D4** |
| ボタン 他端 | GNDライン |
| 5.1kΩ | Nano **D4** ↔ 5Vライン |
| 1µF | Nano **D4** ↔ GNDライン |

- **D4 と D5 の両方に外付けプルアップ（5.1kΩ）とコンデンサ（1µF）が必須。** どちらもモーター回転中および直後に読むため、内蔵プルアップ（20〜50kΩ）では高インピーダンスすぎてブラシノイズを拾う
- **D13 のオンボードLEDは他と共用していない。** 動作表示に自由に使える
- 2SK4017 は型番面から見て左から **G, D, S**
- **5V は Nano の 5V ピンへ入れる。** VIN に入れるとレギュレータを通るため7V以上が必要になる

### 書き込み時の手順

**ACアダプタを抜いてから USB を接続すること。**

外部5VとUSBの5Vが同時に接続されると、2つの電源が押し合う。Digispark はこの状態で使ううちにUSB部が死に、最終的にボード全体が動作しなくなった。Nano でも同じ経路があるため、運用ルールとして固定する。

Nano は雌ピンヘッダでソケット化しておくと、故障時に基板ごと差し替えられる。

| ~~**1回転で本当に1ピッチ進むか**~~ | **検証済み。成立した**（下記） |

最後の項目が本方式の生命線だった。**実機で検証し、成立を確認した。**

### 1ピッチ送りの検証結果

6つの部屋にサイコロを1個ずつ入れ、蓋を閉じて6回動かした。

- **1回転ごとに、ちょうど1個ずつ落下**
- 6回で6個、過不足なし
- 途中で2個出たり、出ない回があったりはしない

カリカリとは粒径も形状も全く異なるサイコロで通ったため、機構としての余裕も確認できた。**弾倉式スクリューコンベアは成立する。**

## 9. 構想：体重記録アプリとの連携

**本節は構想であり、確定仕様ではない。** 実装時期は §7 の実測値と獣医の確認が揃ってから。

### やりたいこと

体重記録アプリ（`neko-weight`）に1日の給与グラム数を割り出させ、**9で割って「1部屋あたり何グラムか」を出す**。現状の装填は目分量だが、これが出れば秤で測って入れられる。

アプリ側は既に `pets`（猫ごとの識別）と `records`（日付ごとの体重、抱っこ測定から人の体重を引いたもの）を localStorage に持っている。**体重の時系列は既にある。** 足りないのは以下の3つだけ。

| 不足している入力 | 入手元 |
|---|---|
| 猫ごとの理想体重 | 獣医（BCS判定が必要。8kgの「理想」は自明ではない） |
| フードの kcal/100g | 袋の表示（銘柄で300〜450と幅がある） |
| 減量時の係数と目標ペース | 獣医 |

### 計算

```
RER      = 70 × (理想体重kg)^0.75      … 安静時エネルギー要求量
1日kcal  = RER × 0.8〜1.0              … 減量時の係数。要獣医確認
1日g     = 1日kcal ÷ (kcal/100g ÷ 100)
1部屋g   = 1日g ÷ 6
```

試算（理想体重6.0kg、400kcal/100gと仮定した場合）：

```
RER   = 70 × 6.0^0.75 ≈ 268 kcal/日
給与  = 268 × 0.8      ≈ 215 kcal/日
1日   = 215 ÷ 4        ≈ 54 g/日
1部屋 = 54 ÷ 6         ≈ 9 g
```

### 機構設計への逆流

**この「1部屋あたりのグラム数」は §7 の未実測項目そのもの。** かさ密度を0.4g/mL前後とすると1部屋あたり15mL程度となり、パイプ内径とピッチをここから逆算できる。

つまりアプリ側の計算が先に出れば機構の寸法決めが進む。**順序としてはアプリを先に作ってもよい。**

### 本体はフィードバックループ

計算式は出発点にすぎない。**実際の体重推移を見て給与量を補正する**部分が本題であり、それができるのは体重の時系列を持つアプリだけである。

- 週あたりの減量率を算出する（猫は **0.5〜1%/週**、上限でも2%）
- 速すぎればグラム数を増やす。**肝リピドーシスは急激な減量が引き金になる**
- 遅すぎる・横ばいならグラム数を減らす

「54g」と出して終わりではなく、「先週 -1.8%/週。速すぎる。60gに増やすこと」と言えるのが理想形。

### 限界

**本装置は「対象猫が食べた量」を保証しない。** 対象猫が高所に登らないことは確認済みだが、スリム猫が床に降りてくるのは止められない。横取りされた分だけ実際の摂取量は計算値を下回り、**体重が落ちすぎる方向にズレる**。

したがって計算値を鵜呑みにせず、実測体重で補正するループが必須となる。
