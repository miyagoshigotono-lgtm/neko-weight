## 1. 目的と背景

猫4匹（8kg台1匹＝以下「対象猫」、5kg台3匹）を飼育。対象猫の減量が目的。

全体の作戦は2本立てで、本装置はそのうち片方を担う。

| | 対象猫（8kg台） | スリム猫3匹（5kg台） |
|---|---|---|
| 餌の場所 | 床（本装置） | 高所（自由摂取） |
| 量の制御 | 本装置で1日分を少量頻回に分割 | 制御しない |

**前提（確認済み）**：対象猫は高所に絶対に登らない。この前提の上に作戦全体が成立している。

**この装置が解く問題**：床に置き餌をすると対象猫が食べ放題になる。かといって識別機構（体重・画像・RFID）はコストと複雑さが見合わない。よって「識別せず、1日分を機械が小分けして時間差で出す」方式を採る。

## 2. 機構：弾倉式スクリューコンベア

### 基本方式

水平に置いた円筒パイプの中に一条スクリューを収める。**各ピッチが1回分の小部屋（弾倉）として機能する。**

- ピッチ数：**9**（＝1日9回分）
- 1回の給餌 ＝ **スクリューを正確に1回転** ＝ 全部屋が1ピッチ前進 ＝ 9段目の中身が餌皿へ落下
- **ホッパー・タンクは持たない。** パイプ自体が貯蔵部を兼ねる

### なぜこの方式か

一般的なスクリューコンベアはホッパーから重力供給し、吐出量は充填率に依存する。本方式は**朝の手作業で各部屋に小分けする**ため、スクリューの容積特性に依存しない。したがって**吐出量の校正が不要**。

### 装填

パイプの上半円がヒンジで開く。毎朝、蓋を開けて各部屋に目分量で投入する。

- **ヒンジは出口と反対側（奥側）に置く。** 出口側に開くと開けた瞬間に餌が皿へ落ちる
- 上半割は洗浄性のためでもある（PLAの積層溝に油脂が溜まるため、分解洗浄できる構造が必須）

### 回転止めについて

内壁にリブは**設けない**。

- 低速回転では餌が重力に逆らって壁を登り、スクリューと共回りする事態は起きにくい
- 代わりに**パイプ内壁とスクリュー外径のクリアランスを狭く**取り、羽根を部屋の仕切りとして機能させる
- **クリアランスは「粒径の1/3〜1/2」を避けること。** その領域は粒が楔になって固着する最悪域。取るべきは 0.3〜0.5mm 程度のほぼゼロ側
- ペットボトル流用は**不採用**。断面が真円でなく、狭クリアランスが成立しないため。**パイプも3Dプリントする**

### 出口

- パイプ下面に**ちょうど1ピッチ幅**の開口を設ける
- **スクリューの羽根は開口部で終わらせる。** 羽根が開口より先に伸びていると、落ちるべき餌を押し越す
- 開口の下に餌皿を置く

### 造形

- パイプは上下半割で、それぞれ寝かせてプリント（反り対策・真円精度）
- 合わせ面は羽根の外径より僅かに逃がし、粒の噛み込みを防ぐ
- スクリューは芯に M6 全ネジ棒を通す前提で設計（軸方向に立てると層剥離で折れる）
- 猫に叩かれても倒れない重量と固定、および開かないラッチ

## 3. 駆動系

### 減速機（手持ち部品で自作）

手持ちのプラ歯車詰め合わせセットを使用。**ウォームギヤ1段 + 平歯車2段**の構成。

```
130系DCモーター → ウォーム(約1:40) → 平歯車2段(約1:9) → スクリュー軸
                                            合計 約1:360
```

- **ウォームのセルフロックが利点。** 出力側から逆転しないため、対象猫が皿側からスクリューを突いても動かない
- **ウォーム軸の軸受けは長穴（スロット）にする。** 中心距離と噛み合い深さがシビアなため、組んでから調整できるようにする
- 釘は2段目以降の軸に使用。ウォームはモーター軸へ直接圧入
- プラ製ウォームの高速回転による摩耗は問題にならない。稼働は**1日9回×約3秒＝27秒**のみ

### 代替案

自作ギヤボックスが成立しない場合：秋月「DCギアードモーター 6V 減速比1:298」（¥900、無負荷35rpm / 定格28rpm、停動トルク1kgf・cm、停動電流140mA、軸φ3mm Dカット）。

**設計上の注意**：給餌器の成否をギヤボックスに賭けないこと。本題はスクリューとパイプの検証であり、減速機はそこへ至る道具に過ぎない。

## 4. 1回転の割り出し

スクリュー軸に円板を固定し、縁にネオジム磁石を1個埋める。**リードスイッチ MKA-10110**（A接点：磁石が近づくとON、5個入¥290、接点150V/0.5A、接触抵抗0.1Ω）で検出する。

- ガラス管に窒素封入されており、餌の粉・湿気の影響を受けない。摺動がないため摩耗もしない
- 磁石の強さ・距離・向きによる感度は**現物合わせで詰める**

### 検討したが採らなかった案

**自己保持回路**（MOSFETと並列に接点を入れ、マイコンは起動のキックのみ、停止は回路が自律的に行う）は部品もソフトも最小になるが、**原点で「開く」B接点が必要**。MKA-10110はA接点のため、この回路にはマイクロスイッチ＋カム（原点に30〜45度の切り欠き）が必要になる。今回は部品点数よりも構成の素直さを取り、**マイコン検出方式**を採用する。

## 5. 制御（Digispark / ATtiny85）

### ピン割り当て

| ピン | 用途 | 備考 |
|---|---|---|
| P0 | MOSFETゲート出力 | |
| P1 | 装填完了ボタン入力 | 内蔵プルアップ、押下でGND。オンボードLED直結だが入力として使用可 |
| P2 | リードスイッチ入力 | 内蔵プルアップ、磁石検出でGND |
| P3 / P4 | 使用しない | USB D-/D+ に直結、プルアップ付きのため不安定 |
| P5 | 使用しない | RESET。使用にはヒューズ書き換えが必要 |

### 時刻管理

**RTCは使わない。** 毎朝の装填という工程が必ず入るため、**装填完了ボタンの押下時刻を起点**として相対時間で計時する。絶対時刻を知る必要がない。

- **WDTによるスリープ計時は禁止。** WDT発振器は128kHzの内蔵RCで誤差が±10%あり、1日で1〜2時間ずれる
- **`millis()` で計時する。** コンセント給電のため省電力は不要。内蔵発振の誤差は約1%で、1日なら十数分に収まり、毎朝リセットされるため累積しない

### 給餌スケジュール

起点から9回。**合計を14〜16時間に収める**（装填が多少遅れても最後が深夜にならないため）。

初期値の案：起点+60分に1回目、以降105分間隔、9回目は起点+15時間。**要調整。**

対象猫の睡眠時間帯は避ける（毎回起こしてしまうため）。具体的な時間割は運用しながら詰める。

### 1回の給餌シーケンス

```
1. P0 を HIGH → モーター回転開始
2. 開始から1秒間はリードスイッチを無視する（不感帯）
3. P2 が LOW（磁石検出）→ P0 を LOW → 停止
4. 10秒経っても検出しなければ強制停止し、その回は諦める（タイムアウト）
```

**不感帯（手順2）は必須。** 停止時の惰性で磁石の位置を僅かに行き過ぎるため、次に回し始めた瞬間にまだ磁石の上にいると「即検出→即停止」となり、1ピッチ回らずに終わる。

**タイムアウト（手順4）も必須。** 詰まった際に「検出するまで回り続ける」と、モーターが焼けるかギヤが舐めるか、スクリューが折れる。詰まりの通知機能は不要（朝夕必ず様子を見る運用のため）だが、**機械を保護するための上限は要る**。

### 停電・再起動時の挙動

給餌回数のカウントは失われる。**復帰後は待機状態とし、人がボタンを押すまで一切動かさない。**

これは意図的な設計。停電を検知して「残り回数を出す」といった復旧動作を入れると、誤爆で1日分をまとめて排出する事故につながる。朝夕確認する運用なので、人がボタンを押し直せば済む。

### 手動操作

ボタン長押しで1回転だけ実行する機能を設ける。装填時の位置合わせと動作テストに使う。

## 6. 回路

```
              5V(+) ──┬──────────────┐
                      │              │
                    [1N4007]      [モーター]
                    (カソード＝＋側)  │  ┬ 0.1µF（端子間）
                      │              │  ┴
                      └──────────────┤
                                     │
                                   Drain
        Digispark ──[220Ω]──── Gate  2SK4017
          (P0)              │      Source
                          [10kΩ]      │
                            │         │
              GND ──────────┴─────────┴──── 5V(−)
```

| 部品 | 役割 |
|---|---|
| 2SK4017 | モーターのスイッチング。130系は停動1〜2A流れるため2N7000（200mA）では焼ける |
| 1N4007 | 逆起電力の還流。**これが無いとMOSFETもリードスイッチも壊れる。** リードスイッチの接点は溶着すると止まらなくなる |
| 220Ω | ゲート直列。突入電流からマイコン出力を保護 |
| 10kΩ | ゲートプルダウン。**無いと電源投入時にモーターが勝手に回る** |
| 0.1µF | モーター端子間。ブラシノイズ抑制 |

- **GNDは必ず共通にする**（電源を分ける場合もマイナス側は接続）
- 電源：本番は 5V USB ACアダプタ。ベンチテストは単3×2本（3V）
- **電池運用は不採用。** Digisparkの待機電流が15〜20mAあり、単3×4本でも約6日しか持たない。モーターの消費は全体の0.2%に過ぎず、食っているのは待機中のマイコン。加えて新品アルカリ4本は6.4Vとなり、ATtiny85の最大定格5.5Vを超える

## 7. 実装着手前に実測が必要な事項

以下が埋まるまで寸法は確定できない。

| 項目 | 何が決まるか |
|---|---|
| フードの粒径（長径・短径） | ピッチ、パイプ内径、クリアランス |
| 1ピッチあたりのグラム数 | 1日の総量が足りるか |
| 対象猫の1日摂取量、獣医による適正カロリー | そもそも装置が必要か、1日量をいくつにするか |
| ウォームホイールの有無・歯数、各歯車の歯数とモジュール | 総減速比、ギヤボックス寸法、中心距離 |
| モーターの無負荷電流・停動電流 | 電源容量、MOSFET選定の妥当性 |
| **1回転で本当に1ピッチ進むか** | 弾倉方式が成立するか（色違いの1粒を目印に10回転させて確認） |

最後の項目が本方式の生命線。上半円が開くため目視で検証できる。

## 9. 構想：体重記録アプリとの連携

**本節は構想であり、確定仕様ではない。** 実装時期は §7 の実測値と獣医の確認が揃ってから。

### やりたいこと

体重記録アプリ（`neko-weight`）に1日の給与グラム数を割り出させ、**9で割って「1部屋あたり何グラムか」を出す**。現状の装填は目分量だが、これが出れば秤で測って入れられる。

アプリ側は既に `pets`（猫ごとの識別）と `records`（日付ごとの体重、抱っこ測定から人の体重を引いたもの）を localStorage に持っている。**体重の時系列は既にある。** 足りないのは以下の3つだけ。

| 不足している入力 | 入手元 |
|---|---|
| 猫ごとの理想体重 | 獣医（BCS判定が必要。8kgの「理想」は自明ではない） |
| フードの kcal/100g | 袋の表示（銘柄で300〜450と幅がある） |
| 減量時の係数と目標ペース | 獣医 |

### 計算

```
RER      = 70 × (理想体重kg)^0.75      … 安静時エネルギー要求量
1日kcal  = RER × 0.8〜1.0              … 減量時の係数。要獣医確認
1日g     = 1日kcal ÷ (kcal/100g ÷ 100)
1部屋g   = 1日g ÷ 9
```

試算（理想体重6.0kg、400kcal/100gと仮定した場合）：

```
RER   = 70 × 6.0^0.75 ≈ 268 kcal/日
給与  = 268 × 0.8      ≈ 215 kcal/日
1日   = 215 ÷ 4        ≈ 54 g/日
1部屋 = 54 ÷ 9         ≈ 6 g
```

### 機構設計への逆流

**この「1部屋あたりのグラム数」は §7 の未実測項目そのもの。** かさ密度を0.4g/mL前後とすると1部屋あたり15mL程度となり、パイプ内径とピッチをここから逆算できる。

つまりアプリ側の計算が先に出れば機構の寸法決めが進む。**順序としてはアプリを先に作ってもよい。**

### 本体はフィードバックループ

計算式は出発点にすぎない。**実際の体重推移を見て給与量を補正する**部分が本題であり、それができるのは体重の時系列を持つアプリだけである。

- 週あたりの減量率を算出する（猫は **0.5〜1%/週**、上限でも2%）
- 速すぎればグラム数を増やす。**肝リピドーシスは急激な減量が引き金になる**
- 遅すぎる・横ばいならグラム数を減らす

「54g」と出して終わりではなく、「先週 -1.8%/週。速すぎる。60gに増やすこと」と言えるのが理想形。

### 限界

**本装置は「対象猫が食べた量」を保証しない。** 対象猫が高所に登らないことは確認済みだが、スリム猫が床に降りてくるのは止められない。横取りされた分だけ実際の摂取量は計算値を下回り、**体重が落ちすぎる方向にズレる**。

したがって計算値を鵜呑みにせず、実測体重で補正するループが必須となる。
